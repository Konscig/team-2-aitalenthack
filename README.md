# team-2-aitalenthack

## Web PoC пути перевода

Автономный прототип живёт в `app.py`: он повторяет путь «Платежи → перевод за рубеж → страна → способ → реквизиты» и не выполняет настоящие платежи. Он отражает актуальный pivot: обычный перевод доступен всегда, а дополнительный контекст появляется только после сильного frame и пройденного execution gate.

```bash
python -m pip install -r requirements.txt
python -m uvicorn app:app --reload
```

- Прототип: `http://127.0.0.1:8000`
- Swagger: `http://127.0.0.1:8000/docs`
- Три сценария проверяются в панели справа: сильный frame с пройденным gate, слабый frame и непройденный gate.

Только сильный подтверждённый сценарий создаёт push. Его ссылка передаёт фикстурную страну и открывает привычный экран выбора способа; после ввода суммы рядом с актуальным demo-quote появляется factual hint. При слабом frame или непройденном gate продукт молчит: нет push, hint, прогноза или совета ждать.

## Документация

Вся проектная документация находится в папке [`docs`](docs). Она описывает кейс «Выгодный момент для трансграничного перевода»: как определить полезный момент для пуша о переводе, проверить качество сигнала и безопасно провести пользователя от уведомления к привычному переводу.

### С чего начать

1. [`CASE.md`](docs/CASE.md) — исходная постановка от кейсодателя: бизнес-проблема, границы задачи, критерии оценки и ожидаемый результат.
2. [`BRIEF.md`](docs/BRIEF.md) — рабочая декомпозиция кейса для команды: цели, ограничения, решения для первой версии и планируемые результаты.
3. [`QA_ALIGNMENT.md`](docs/QA_ALIGNMENT.md) — ответы и уточнения кейсодателя, а также решения команды и реестр допущений.
4. [`CONTEXT_PACK.md`](docs/CONTEXT_PACK.md) — общий контекст для проектирования: пользователи, сценарии, гипотезы и ограничения.

### Логика чтения

Для понимания задачи достаточно пройти путь `CASE → BRIEF → QA_ALIGNMENT → CONTEXT_PACK → USER_STORY_MAP`. Для UX-проработки затем используйте обе Journey Map и `screenshots/`; для проверки реализуемости — `NFR` и Validation Report; перед исследованием пользователей — папку `personas/` и `interviews/`.

## Нормализация курсов ЦБ РФ

Offline-нормализация запускается только после raw ingestion:

```powershell
python -m src.normalization --raw-dir data/raw/cbr --output-dir data/interim
```

`unit_rate` определяется как RUB за одну единицу валюты получателя
(`VunitRate` ЦБ, либо `Vcurs / Vnom`, если официальное поле отсутствует).
Поэтому для отправителя, переводящего RUB, **меньший `unit_rate` означает более
выгодный момент, больший — менее выгодный**.

`fx_quote_time.parquet` и `cbr_fx_normalized.parquet` содержат только реальные
наблюдения ЦБ. `fx_calendar_time.parquet` отдельно расширяет ряд до календарных
дней через forward fill и маркирует такие строки `is_new_quote=False`.
Forward-filled строка никогда не считается новым движением рынка.

## Актуальные датасеты и признаки

Production snapshot запрошен за `2019-01-01` — `2026-09-03`; фактические
официальные котировки ЦБ доступны с `2019-01-10` по `2026-09-03`. Собраны TJS,
UZS, KGS, AMD, KZT, USD, EUR и CNY: по 1 889 наблюдений на валюту, 15 112
quote-time строк суммарно.

- `data/interim/fx_quote_time.parquet` — только реальные наблюдения ЦБ;
- `data/interim/fx_calendar_time.parquet` — календарное представление восьми валют;
- `data/features/base_market_features.parquet` — 64 базовых признака для пяти целевых коридоров;
- `data/features/fx_features_daily.parquet` — 104 поля с base, reversal и cross-currency features на quote-time;
- `data/features/fx_features_calendar_daily.parquet` — отдельное ежедневное представление: 13 970 строк, добавленные даты имеют `is_new_quote=False`;
- `notebooks/01_fx_features_eda.ipynb` — выполненный EDA без labels и моделей.

Полное описание происхождения, слоёв, размеров, semantics, проверок и
ограничений приведено в [`docs/dataset_card.md`](docs/dataset_card.md).
