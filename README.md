# team-2-aitalenthack

## Документация

Вся проектная документация находится в папке [`docs`](docs). Она описывает кейс «Выгодный момент для трансграничного перевода»: как определить полезный момент для пуша о переводе, проверить качество сигнала и безопасно провести пользователя от уведомления к привычному переводу.

### С чего начать

1. [`CASE.md`](docs/CASE.md) — исходная постановка от кейсодателя: бизнес-проблема, границы задачи, критерии оценки и ожидаемый результат.
2. [`BRIEF.md`](docs/BRIEF.md) — рабочая декомпозиция кейса для команды: цели, ограничения, решения для первой версии и планируемые результаты.
3. [`QA_ALIGNMENT.md`](docs/QA_ALIGNMENT.md) — ответы и уточнения кейсодателя, а также решения команды и реестр допущений.
4. [`CONTEXT_PACK.md`](docs/CONTEXT_PACK.md) — общий контекст для проектирования: пользователи, сценарии, гипотезы и ограничения.

### Продуктовая проработка

| Файл | Что внутри и зачем нужен |
| --- | --- |
| [`LEAN_CANVAS.md`](docs/LEAN_CANVAS.md) | Сжатая модель продукта: проблема, сегменты, ценность, метрики и риски. Нужна, чтобы синхронизировать продуктовое решение до детализации. |
| [`USER_STORY_MAP.md`](docs/USER_STORY_MAP.md) | Карта пользовательских историй и приоритетов. Показывает, что должно попасть в первую версию и как проверять результат. |
| [`ELASTIC_JOURNEY_MAP.md`](docs/ELASTIC_JOURNEY_MAP.md) | Путь отправителя, который может выбрать день перевода. Используется для проектирования сценария «увидел сигнал → проверил актуальность → перевёл или отложил». |
| [`INELASTIC_JOURNEY_MAP.md`](docs/INELASTIC_JOURNEY_MAP.md) | Путь срочного отправителя. Фиксирует, что уведомление или устаревший сигнал не должны мешать немедленному переводу. |
| [`NFR.md`](docs/NFR.md) | Нефункциональные требования: воспроизводимость, надёжность, безопасность, комплаенс и требования к будущему пилоту. |
| [`ARTIFACT_VALIDATION_REPORT.md`](docs/ARTIFACT_VALIDATION_REPORT.md) | Проверка согласованности остальных артефактов, найденные риски и итоговый вердикт готовности к прототипу. |

### Исследования и персоны

| [`interviews/AI_CUSTDEV_REINTERVIEW_SYNTHESIS.md`](docs/interviews/AI_CUSTDEV_REINTERVIEW_SYNTHESIS.md) | Сводные выводы из AI CustDev и изменения, которые они предлагают внести в продуктовые артефакты. |

### Референсы текущего интерфейса

Папка [`screenshots/`](docs/screenshots) содержит пять экранов актуального пути зарубежного перевода в приложении. [`screenshots/README.md`](docs/screenshots/README.md) объясняет порядок экранов и две альтернативные ветки после выбора страны и способа перевода. Эти материалы нужны как визуальная основа для прототипа, а не как описание будущего интерфейса.

### Логика чтения

Для понимания задачи достаточно пройти путь `CASE → BRIEF → QA_ALIGNMENT → CONTEXT_PACK → USER_STORY_MAP`. Для UX-проработки затем используйте обе Journey Map и `screenshots/`; для проверки реализуемости — `NFR` и Validation Report; перед исследованием пользователей — папку `personas/` и `interviews/`.
