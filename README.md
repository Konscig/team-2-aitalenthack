# Выгодный момент для перевода

Решение — двухконтурный движок сигналов для трансграничных переводов. На исторических курсах правилами размечаются благоприятные периоды, после чего модель учится по доступным на текущую дату признакам оценивать ближайшую траекторию курса и риск упустить более выгодный момент. В runtime прогноз объединяется с оценкой текущего уровня, отдельными порогами для каждого валютного коридора и коммуникационными ограничениями. Если все проверки пройдены, клиент получает нейтральный push и переходит в стандартный сценарий перевода с актуальным расчётом; в остальных случаях система молчит.


Поддерживаемые коридоры: AMD/RUB, KGS/RUB, KZT/RUB, TJS/RUB и UZS/RUB.

## 0. Запуск

Автономный прототип находится в `app.py`. Он воспроизводит путь «Платежи → перевод за рубеж → страна → способ → реквизиты» и не выполняет реальные платежи.

```bash
python -m pip install -r requirements.txt
python -m uvicorn app:app --reload
```

- Прототип: `http://127.0.0.1:8000`
- Swagger: `http://127.0.0.1:8000/docs`
- В правой панели доступны три сценария: сильный актуальный сигнал, устаревший сигнал и отсутствие сигнала.

Только сильный актуальный сценарий создаёт push. Ссылка из него передаёт страну и открывает стандартный экран выбора способа перевода. После ввода суммы рядом с демонстрационным курсом появляется фактическая подсказка. В остальных сценариях продукт молчит и не предлагает клиенту ждать.

## 1. Идея и схема работы

Решение объединяет два контура, показанные в [презентации проекта](https://docs.google.com/presentation/d/1-mTwJ8UT4rphNEHI6DCbz6XaSxrGJv16InTri9Oja0c/edit):

1. `Golden rules` ретроспективно определяют, как выглядит хороший момент. Эти правила используют фактический курс до и после даты и нужны для разметки истории и оценки качества, но не для принятия решения в runtime.
2. `Time-series prediction` использует только информацию, доступную на текущую дату, и оценивает траекторию курса на ближайшем горизонте.
3. Сигнальный слой объединяет историческую привлекательность текущего курса и прогнозный риск того, что в ближайшие дни появится существенно лучший момент.
4. Коммуникационный слой проверяет свежесть данных, пороги качества, cooldown и клиентские ограничения. Если проверки не пройдены, сообщение не отправляется.

В ноутбуках проверены Naive, ARIMA, ARIMAX, direct Ridge/Gradient Boosting и CatBoost. Наиболее практичным прогнозным референсом оказался direct multi-horizon подход: отдельная модель для каждого коридора и горизонта H1–H5. Он превзошёл Naive по H5 в четырёх из пяти коридоров, но выигрыш оказался небольшим. Поэтому прогноз курса используется как один из признаков решения, а не как обещание будущего курса.

## 2. Proof of concept: разметка исторических данных

Golden dataset содержит два ретроспективных сценария и один причинный сценарий, доступный уже на дату `T`:

- `good` — находился ли день рядом с локально лучшим курсом;
- `closing` — вышел ли курс из хорошей зоны перед устойчивым ухудшением;
- `positive_market_fact` — наблюдается ли положительный факт в текущей и прошлой динамике курса.

Курс нормализован как количество RUB за одну единицу валюты получателя: чем значение ниже, тем выгоднее перевод для отправителя.

Для выбора определения `good` были проверены восемь правил-гипотез, пять горизонтов и три допуска — всего 120 комбинаций. Итоговое правило:

```text
good = rate_T <= min_rate × (1 + 100 / 10 000)
```

То есть день считается хорошим, если его курс не более чем на 1% хуже минимума в 21-дневном окне. Такое определение выделяет выгодное плато, а не одну точку абсолютного минимума.

`closing = 1`, если день уже не относится к `good`, курс находится на 1–2% выше минимума предыдущих десяти дней, а медиана следующих десяти дней минимум на 1% хуже текущего курса. Будущие значения здесь допустимы только потому, что это историческая целевая разметка.

`positive_market_fact = 1`, если курс снижался три обновления подряд, улучшился минимум на 1% за семь календарных дней или оказался выгоднее не менее 90% значений предыдущих 30 дней. Сценарий рассчитывается без будущих данных и даёт более регулярный, но менее приоритетный информационный повод. При конфликте действует порядок `good → closing → positive_market_fact`, затем применяются cooldown четыре дня и лимит не более двух push в неделю.

В модель запрещено передавать `good`, `closing` и любые диагностические поля `future_*` или `centered_*`. Обучение и проверка выполняются хронологически, с зафиксированным тестовым периодом и без подбора параметров на нём.

Полная методология и команды воспроизведения: [docs/golden_label_methodology.md](docs/golden_label_methodology.md).

## 3. Модель и формирование сигнала в runtime

Целевой runtime-контур состоит из следующих этапов:

1. Загрузить свежую котировку и привести её к единой семантике RUB за единицу валюты получателя.
2. Рассчитать только причинные признаки на дату `T`: доходности и momentum, волатильность, положение относительно прошлых минимумов и максимумов, скользящий percentile и межвалютный контекст.
3. Построить direct multi-horizon прогноз для конкретного валютного коридора. Отдельные модели оценивают курс на H1–H5 обновлений; из прогнозного пути рассчитываются ожидаемый лучший курс и `predicted regret` текущего решения.
4. Применить правило коридора. Оно объединяет историческую привлекательность, преимущество относительно недавнего курса и ограничение прогнозного regret. Единые пороги для всех валют были отклонены как нестабильные.
5. Применить коммуникационную политику: абсолютный порог качества, cooldown, отсутствие повторов, свежесть котировки и доступность исполнимого банковского курса.
6. Отправить нейтральный сигнал только после прохождения всех проверок. Иначе система не вмешивается в обычный перевод.

На locked test правила, настроенные отдельно по коридорам, дали uplift не ниже 1,3 во всех пяти коридорах, средний uplift — 3,93.

Метрики сигнальных сценариев:

| Сценарий | Uplift | Hit Rate | F0,5 | Precision |
| --- | ---: | ---: | ---: | ---: |
| `good` | Не рассчитано | Не рассчитано | Не рассчитано | Не рассчитано |
| `closing` | Не рассчитано | Не рассчитано | Не рассчитано | Не рассчитано |
| `positive_market_fact` | Не рассчитано | Не рассчитано | Не рассчитано | Не рассчитано |

Значения должны рассчитываться на едином out-of-time периоде после фиксации правил каждого сценария. Средний uplift 3,93 выше относится к отдельному эксперименту с per-corridor good-day rules и поэтому не перенесён в таблицу.

Полное описание происхождения, слоёв, размеров, semantics, проверок и ограничений приведено в [`docs/dataset_card.md`](docs/dataset_card.md).

### Оценка алгоритмов сигналов

Модель должна вернуть по каждой дате и коридору `good_pred` и `closing_pred`; probability/score и factual-кандидат необязательны. Один вызов применяет коммуникационную политику и считает classification, safety hit, экономическую выгоду, policy-matched random, частоту и кучность сразу для всех коридоров и `h = 1/3/5/10/20`:

```python

result = evaluate_predictions(predictions, golden_labels, calendar)
result.save("reports/evaluation/my_model")
```

## Ограничения

- Курсы ЦБ используются как публичный proxy и не равны клиентскому курсу банка с учётом спреда и комиссии.
- Точность прогноза недостаточна для обещания будущего курса; клиенту показывается только проверяемый факт о текущем состоянии.
- Веб-прототип не выполняет платежи и использует демонстрационные котировки.
- Перед пилотом необходимы интеграция с исполнимым банковским курсом, walk-forward-проверка на новом периоде и пользовательское A/B-тестирование.
