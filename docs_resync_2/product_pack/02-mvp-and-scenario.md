# MVP и основной пользовательский сценарий

## Границы MVP

| Входит в MVP | Не входит в MVP |
| --- | --- |
| Пять RUB-коридоров: AMD, KGS, KZT, TJS, UZS. | Прогноз курса, совет ждать или оценка «плохого момента». |
| Обычный путь перевода с актуальным quote. | Гарантия курса, обещание экономии или персональная рекомендация. |
| Редкий factual hook только при `strong frame + execution gate`. | Показ hook при слабом/пограничном frame. |
| Логирование frame, quote, hook и outcome для пилота. | Реальный платеж, персонализация по истории, автоматический перевод. |
| A/B holdout и guardrails безопасности исполнения. | Rollout без проверки spread, ликвидности и вреда клиенту. |

Текущий Web PoC — технический прототип предыдущей гипотезы и имеет статус
**«в переработке под contextual quote»**. Его demo push/status-сценарии не
являются интерфейсом MVP.

## Основной сценарий

### Сильный и подтверждённый frame

1. Рыночный слой на данных, доступных на дату `T`, помечает frame как сильный.
2. Execution gate проверяет реальный client quote, spread, ликвидность,
   маршрут и операционные ограничения.
3. Клиент открывает привычную форму перевода и видит актуальную сумму списания
   и сумму к получению.
4. Рядом с quote появляется короткий factual hook о текущем/прошлом состоянии
   рынка. Он не содержит прогноза или обещания выгоды.
5. Клиент либо продолжает обычный перевод, либо закрывает экран; оба действия
   допустимы и измеримы.

### Во всех остальных случаях

Клиент видит только обычный перевод и актуальный quote. Для критичной операции
это единственный допустимый путь: продукт не просит ждать и не добавляет
препятствий.

## Предварительные критерии успеха

| Уровень | Критерий |
| --- | --- |
| Понимание | В UX-тесте клиент правильно объясняет, что hook — контекст, а не прогноз/совет. |
| Безопасность пути | При любом состоянии клиент может сразу завершить обычный перевод; для срочного сценария нет ухудшения завершения или роста ранних выходов. |
| Качество frame | Walk-forward показывает качество сильных frames выше случайного дня при контроле частоты и кластеризации. |
| Исполнение | Client quote не ухудшается относительно baseline; нет неприемлемого роста spread, отказов или переоценок. |
| Продуктовый эффект | В рандомизированном holdout есть положительный инкрементальный эффект на завершённые переводы и чистый объём, а не только CTR. |
